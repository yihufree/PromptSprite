## 1. 打包前准备

### 1.1 Python 环境

| 项目     | 要求                        | 核对命令                          |
| ------ | ------------------------- | ----------------------------- |
| Python | 3.12（64-bit）              | `python -V` → `Python 3.12.x` |
| 虚拟环境   | 项目根 `.venv`（推荐，打包脚本优先使用它） | 见下                            |
| 终端     | 管理员身份打开 PowerShell/CMD    | 仅影响开发态运行全局热键，不影响打包本身          |

创建/使用虚拟环境（若尚无 `.venv`）：

```powershell
cd C:\PSA
python -m venv .venv
```

> 说明：`build.py` 会自动优先使用 `C:\PSA\.venv\Scripts\python.exe`（存在时），否则退化为当前解释器。因此**若存在 `.venv`，务必先在其中装好依赖**，避免装错解释器。

### 1.2 依赖安装

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

- 运行依赖共 6 项（`requirements.txt` 实测）：`customtkinter / Pillow / pyperclip / openpyxl / keyboard / pystray`（`python-dateutil` 已于 2026-08-18 移除，勿再装回）；
- **V1.7.0 未新增任何第三方依赖**，`requirements.txt` 无需改动；
- `pyinstaller` 不必手工装：`python build.py` 第 1 步检测缺失会自动安装。

### 1.3 与打包相关的目录结构（速览）

```
C:\PSA\
├── build.py                            # 一键打包脚本（无命令行参数，自动 7 步，见第 2 章）
├── requirements.txt                    # 运行依赖（6 项）
├── app\config.py                       # APP_VERSION / BUILTIN_* 版本 / 目录常量（版本号唯一来源）
├── app\resources\builtin_manual.md     # 内置手册（约 90 条，版本串见 1.5）
├── app\resources\builtin_prompts.db    # 内嵌完整库（打包时由 build.py 从 data\prompts.db 同步生成）
├── data\prompts.db                     # ★开发态主库＝发布数据唯一来源
├── Icons\PSicon.png                    # 图标源（打进 EXE，托盘/窗口用）
├── build\PromptSprite.spec             # PyInstaller 配置（onefile + windowed）
├── build\generate_icon.py              # PSicon.png → build\app.ico
├── build\build.bat                     # 备选批处理（仅快速验证用，见 2.2 的局限）
└── dist\                               # 产物目录（版本化 EXE + 可选 data\）
```

> 数据量参考（2026-09-09 对 `data\prompts.db` 实测）：**2556 条目 / 173 分类 / 11 根目录 / 4 项目类别**。README 徽章写的"2555 条精简模板"是历史口径；**发布前以打包当日 `data\prompts.db` 实际数据为准**（首次建库后"关于/状态栏"条数与内置库一致即可，见第 4 章）。

### 1.4 内置模板库同步（data\prompts.db → builtin_prompts.db）

机制（对应 `build.py::_prepare_builtin_db`，2026-08-18 第 023 条）：

- **每次 `python build.py` 第 4 步自动执行**：把开发态最新主库 `data\prompts.db` 覆盖复制为 `app\resources\builtin_prompts.db`（spec 的 `datas` 引用它，随 EXE 内嵌）；
- 打包态 EXE 首次运行（exe 旁尚无 `data\prompts.db`）时，由 `main.py::_ensure_initial_db()` 把该内嵌库复制到 exe 同目录 `data\`，做到"开箱即用最新数据"；**已有 data 文件时绝不覆盖**（保护用户数据）；
- 若 `data\prompts.db` 不存在，脚本只告警不报错——此时 EXE 将不含完整库，仅剩内置手册导入流程，属异常发布，务必避免。

手工同步等价命令（仅在跳过 build.py 直接 PyInstaller 时使用）：

```powershell
Copy-Item -Force C:\PSA\data\prompts.db C:\PSA\app\resources\builtin_prompts.db
```

同步前确认（防呆检查）：

1. `data\prompts.db` 已通过迁移向导完成根目录/项目类别归属，无"未分配"状态；
2. **该库已按隐私要求清理**：不含个人/机密内容（含历史删除留在回收站 trash 表或备份中的快照——发布前需确认是否应清除，见 FAQ-3）；
3. 同步后可对比两文件大小一致、用 SQLite 数一遍条数，确认与发布说明一致。

### 1.5 内置手册版本机制（BUILTIN_MANUAL_VERSION）与注意点

代码位置：`app\config.py` `BUILTIN_MANUAL_VERSION = "007-2026-08-18"`；启动逻辑在 `app\main.py::main()` 第 4 步：

- 每次启动读取 `meta.builtin_manual_version`，**仅当与 `BUILTIN_MANUAL_VERSION` 不一致时**才触发一次内置手册导入（进度条窗口），完成后把该版本号写回 meta；
- 导入为 **"非破坏性合并"**（2026-08-18 P0-2 修复）：分类按名复用、条目按名 upsert，**不会清空任何现有数据**——所以"改版本号→重导入"对老用户是安全的。

注意点（打包人必读）：

1. **改了 `builtin_manual.md` 内容却忘了升 `BUILTIN_MANUAL_VERSION` → 老安装包不会重新导入**（meta 仍是旧值，等于白改）；
2. 反之只要升版本号（如改为 `"008-2026-09-09"`），老用户下次启动会自动触发合并导入；
3. 版本串无固定格式，但务必**整串变更**且与 meta 历史值不同，习惯写法 `"编号-YYYY-MM-DD"`；
4. 内嵌完整库与手册是两套互补机制：全库负责"新用户开箱即用全量数据"，手册负责"版本升级时的增量合并补丁"。若某轮数据全量进了 `data\prompts.db`（会随 build 内嵌），新装用户直接拿全库，无需再靠手册。

### 1.6 打包前回归测试（必做，全过才允许打包）

```powershell

# ② 主界面 GUI 自动化回归（需桌面环境，V1.5.0 起维护）
python -m app.gui_self_test

```

## 2. 正式打包命令与流程

### 2.1 推荐方式：一键打包（唯一正规流程）

```powershell
cd C:\PSA
python build.py            # 若 .venv 存在会自动使用 .venv\Scripts\python.exe
```

`build.py` 自动完成 7 步（对照源码 `build.py::main()` 逐一核对，无需手工分步）：

| 步   | 动作                                                                                                     | 对应实现                              |
| --- | ------------------------------------------------------------------------------------------------------ | --------------------------------- |
| 0   | 选定解释器：优先 `.venv\Scripts\python.exe`，否则当前解释器                                                            | `PY` 变量                           |
| 1/7 | `pyinstaller` 缺失则自动 `pip install pyinstaller`                                                          | `main()` step 1                   |
| 2/7 | `pip install -r requirements.txt`（每次执行，幂等）                                                             | step 2                            |
| 3/7 | `build\generate_icon.py` 由 `Icons\PSicon.png` 生成 `build\app.ico`                                       | step 3                            |
| 4/7 | **同步内置完整库**：`data\prompts.db` → `app\resources\builtin_prompts.db`                                     | `_prepare_builtin_db()`           |
| 5/7 | `python -m PyInstaller --noconfirm --clean build\PromptSprite.spec`（在项目根执行，产物 `dist\PromptSprite.exe`） | step 5                            |
| 6/7 | **更新 EXE 旁数据目录**：复制 `data\prompts.db` → `dist\data\prompts.db`（只动该文件，保留 dist\data 下已有 images/backup 等） | `_update_dist_data()`             |
| 6.5 | **按规则重命名产物**为 `PromptSprite_<YYMMDD>_V<版本号>.exe`（同名先删再改，防 PyInstaller 占用）                              | `versioned_exe_path()` + rename 段 |
| 7/7 | 校验产物存在并打印大小                                                                                            | step 7                            |

成功标志（示例）：

```
=== 打包完成：dist\PromptSprite_260909_V1.7.0.exe（约 23 MB）===
```

> **重要**：现行 `build.py` **不接受任何命令行参数**。V7 文档中的 `--onefile / --onedir / --output-dir / --sync-db / --smoke` 等选项**均已不再需要、也未实现**；请勿照 V7 执行。规格固定为 onefile + windowed（见 spec），不存在 onedir 产物。

### 2.2 备选方式：build.bat / 手工 PyInstaller（仅快速验证，不建议用于正式发布）

`build\build.bat` 只做三件事：生成图标 → `PyInstaller --noconfirm --clean build\PromptSprite.spec` → 列出产物。**局限必须知晓**：

- 不自动同步 `builtin_prompts.db`（若该文件缺失，spec 因 datas 找不到文件直接报错；若陈旧，EXE 携带旧库）；
- 不更新 `dist\data\prompts.db`；
- 不改名（产物仍是裸 `dist\PromptSprite.exe`）；
- 假设存在 `.venv`。

手工等效流程（必须补上它缺的步骤）：

```powershell
# 0) 先保证内嵌库最新（缺一不可）
Copy-Item -Force data\prompts.db app\resources\builtin_prompts.db
# 1) 生成图标（app.ico 已入库可跳过，改了 PSicon.png 才需重跑）
.\.venv\Scripts\python.exe build\generate_icon.py
# 2) PyInstaller 打包（在项目根目录执行）
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean build\PromptSprite.spec
# 3) 手工改名（见第 3 章规则）
Move-Item dist\PromptSprite.exe dist\PromptSprite_260909_V1.7.0.exe -Force
```

### 2.3 spec 收集内容核对（build\PromptSprite.spec）

| 类型       | 内容                                           | 去向（EXE 内）    | 用途                                                         |
| -------- | -------------------------------------------- | ------------ | ---------------------------------------------------------- |
| datas    | `app\resources\builtin_manual.md`            | `resources\` | 内置手册（首次/版本变更导入）                                            |
| datas    | `app\resources\builtin_prompts.db`           | `resources\` | 内置完整库（首次运行复制到 exe 旁 data\）                                 |
| datas    | `Icons\PSicon.png`                           | `Icons\`     | 托盘/窗口图标（打包态 `hotkey.py` 读 `sys._MEIPASS\Icons\PSicon.png`） |
| icon     | `build\app.ico`                              | —            | EXE 文件图标                                                   |
| 入口       | `app\main.py`                                | —            | 程序入口                                                       |
| excludes | `matplotlib/numpy/pandas/scipy/IPython/jedi` | —            | 防误收大模块，控制体积                                                |
| 其它       | `name=PromptSprite`、`console=False`          | —            | 单文件、无控制台窗口                                                 |

**关键核对点：没有任何 `data\` 目录被收进 EXE**（spec 的 `datas` 只有上面三项）。`data\`（含用户库/备份/变更包/图片）只存在于 exe 同目录，运行时自动生成/复用。请勿为了"省事"把 `data` 加入 datas——那会把开发机的用户数据与备份打进每个安装包，是隐私事故。

### 2.4 dist 目录的默认行为

- PyInstaller 每次输出裸 `dist\PromptSprite.exe`；`--clean` 只清 `build\` 临时目录，**不清 dist**；
- `build.py` 第 6 步会补 `dist\data\prompts.db`（便于整个 dist 拷走即开箱），**且保留 dist\data 下既有 backups/变更包**——若 dist\data 里残留旧备份，会形成隐私泄漏点（见 FAQ-3/4）；
- 同一台机同一天多次打包：同名目标先删后改，最终只留一个当日版本化 EXE；但**历史遗留的不同版本/不同命名 EXE 不会被自动清理**（当前 `dist` 下实测仍有 `PromptSprite_1.3.0.exe`、`PromptSprite_1.5.0.exe`、`PromptSprite_260907_V1.6.0.exe` 及带旧备份的 `dist\data`）；
- **正式发布前建议：删除 dist 全部旧文件（或整个 dist 目录）后重新一键打包**，保证产物目录干净、无隐私残留。

## 3. 版本号维护与 EXE 命名规则

### 3.1 APP_VERSION 唯一来源：app\config.py

```python
APP_VERSION = "1.7.0"   # 2026-09-08：变更包(v4 summary)格式/命名披露/导入安全向导/…（注释随版本更新）
```

维护规则：

- 只改这一处；`build.py` 靠正则从该文件读版本号用于命名；
- **必须使用英文双引号** `"1.7.0"`。`build.py::_load_version()` 的正则是 `APP_VERSION\s*=\s*"([^"]+)"`，若误写成单引号 `'1.7.0'`，匹配失败将回退为 `0.0.0`，产物会变成 `..._V0.0.0.exe`；
- 版本号要同步到：README 徽章/更新日志、说明书、需求规格、"设置→关于"（读取同一 config，自动一致）、本指南脚注、Release Notes；
- EXE 命名里的"版本号"来自此常量，"日期"来自打包机系统当天日期（`datetime.now()`），两者拼接即为规则名。

### 3.2 EXE 命名规则（2026-09-07 第 7 条起执行）

```
PromptSprite_<最后修改日期YYMMDD>_V<版本号>.EXE
```

示例：`PromptSprite_260909_V1.7.0.EXE`（2026-09-09 打包、V1.7.0）。

> 文件系统上实际扩展名为小写 `.exe`（Windows 不区分大小写），文档/Release 中习惯写作 `.EXE` 等价。日期 YYMMDD＝打包当日（"最后修改"即生成那天），与 GitHub Release 当天日期一致最稳妥。

### 3.3 build.py 重命名逻辑核对点（打包前逐条核）

对照 `build.py` 源码检查以下四处，任何一处与描述不符都需先修脚本再打包：

1. `_load_version()`：正则 `APP_VERSION\s*=\s*"([^"]+)"` 在 `app\config.py` 中应恰好命中一处且取到 `1.7.0`（可临时加 `print(_load_version())` 验证）；
2. `versioned_exe_path()`：拼 `dist\PromptSprite_{datetime.now():%y%m%d}_V{version}.exe`——确认用的是**当天日期**与**config 版本**，无写死版本/日期；
3. 重命名段：`os.path.isfile(EXE_OUT)` 失败要 `sys.exit(1)`；目标同名文件先 `os.remove` 再 `os.rename`（防占用）；改名后第 7 步打印的应是**版本化路径**而非裸 `PromptSprite.exe`；
4. 幂等性：同一天连续两次 `python build.py`，第二次应在改名时先删掉第一次的同名产物再生成，最终 dist 只有一个当日 EXE（旧版本 EXE 不受影响，需手动清理，见 2.4）。

## 6. 常见打包问题 FAQ

**Q1：打包/运行时提示缺少模块（ModuleNotFoundError: customtkinter / PIL / pystray…）**

- 开发态：确认装了依赖的解释器就是运行的解释器——统一用 `.venv`；`python build.py` 第 2 步会自动装；
- 打包态：纯 Python 模块一般由 PyInstaller 自动收集；若仍缺，先看 `build\PromptSprite\warn-PromptSprite.txt`（PyInstaller 每次打包都会生成，列出未收集到的 import 警告），确属漏收的在 spec `hiddenimports` 里补；
- 新 UI 模块（如 V1.7.0 的 `change_import_dialog.py` / `compare_dialog.py`）均被 `main_window.py` import，PyInstaller 静态扫描可收集；个别在函数内延迟 import 的（compare/history 对话框）也建议打包后实测对应入口能打开。

**Q2：杀毒误报 / SmartScreen / 全局热键不灵**

- onefile + UPX（spec `upx=True`）+ 无签名是误报高发组合；发布时可附 sha256 供核对；仍被拦截建议用户"添加信任/白名单"；
- 全局热键 `Ctrl+Shift+P` 使用 keyboard 钩子：**需管理员身份运行或加杀软白名单**；注册失败只弹提示，不影响主功能（属设计行为）；
- 可选：用代码签名证书对 EXE 签名（如 osslsigncode），可显著降低 SmartScreen 拦截，非必需。

**Q3：data 残留与隐私数据检查（发布前必查）**

- `data\` 永远不会被打进 EXE（spec 无此收集项），但**开发机上的 data 会经 build.py 第 6 步同步出 dist\data**；若把整个 dist 打包分发，风险点如下，发布前逐项删除：
  1. `data\backup\*.db` 旧全量备份（如 `snapshot_清理前_*.db` 是含隐私的历史快照，实测仍残留在开发机）；
  2. `data\backup\incremental\*.json` 旧"增量_*"或含他人数据的"变更包"（实测 dist 下仍残留 `增量_DESKTOP-hahaha_2026-09-07.json` 等）；
  3. `Dev_Work_Log\testtmp\` 等测试副本（含 prompts.db / prompts-error.db / 增量 json）；
  4. 回收站 trash 表与 deletion_log.payload（V1.7.0 起删除日志可能带完整快照）——若这些是隐私清理的产物，发布前应在开发库执行"彻底删除/清空回收站"后再同步内置库。
- 干净做法：删除整个 `dist` → 重新 `python build.py` → 仅取版本化 EXE 发布；如需附带初始 data，用全新空目录首次运行生成的干净 data。

**Q4：dist 目录清理**

- `--clean` 只清 PyInstaller 缓存（build\），**不清 dist**；dist 下旧 EXE（实测有 `PromptSprite_1.3.0.exe`、`PromptSprite_1.5.0.exe`、`PromptSprite_260907_V1.6.0.exe`）与旧 `dist\data` 需手动删除，否则会把过期版本/隐私数据一起发出去。

**Q5：EXE 体积**

- V1.6.0 产物约 22.8 MB；体积主要来自 customtkinter/Pillow/解释器与内嵌库；spec 已 excludes 掉 numpy/pandas/matplotlib 等大模块；控制内置库体积（精简模板约 2555+ 条）即可维持体量；UPX 压缩已开启。

**Q6：发布后发现 EXE 内置数据不是最新**

- 原因通常是绕过了 `python build.py`（如直接用 build.bat/手工 PyInstaller），导致 `builtin_prompts.db` 未同步。正规流程第 4 步每次强制覆盖；手工流程务必先补 `Copy-Item data\prompts.db app\resources\builtin_prompts.db`。

**Q7：产物文件名是 V0.0.0 / 无日期版本**

- 见 3.1：`APP_VERSION` 引号必须是英文双引号且恰好一处匹配；改完 config 后重跑 build.py 验证第 6.5 步打印的版本化路径。

**Q8：EXE 首次运行报"内置手册导入失败/无法读取内置手册"或建库为空**

- 多为 spec datas 路径与 `config.builtin_manual_path()/builtin_db_path()`（打包态读 `sys._MEIPASS\resources\`）不一致；核对 spec 三项 datas 均存在且文件名拼写一致，重新打包。开发态不会复现（读 `app\resources\`），务必按第 4 章在空目录实测。
